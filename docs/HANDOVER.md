### App (`app/lib/`), layer-first as the client spec asks
- `core/`: `config/app_config.dart` (API URL via `--dart-define=API_BASE_URL`), `di/` (`sl` service locator, same pattern as the Hope app; `injection.dart` wires everything), `l10n/` (`AppLanguage` fr/ar, `LanguageStore`, date formatting), `network/` (`DioClient` with Accept-Language, `AuthInterceptor` refresh-once-and-replay, `TokenStore`, `ApiFailure`), `router/` (`routes.dart` with the pure `authRedirect`, `app_router.dart` with one `ShellRoute` per role), `theme/` (`brand_colors.dart`: colors, `Accent` families, radii, shadows, breakpoints; `app_text.dart`: the type roles of the spec via `AppText.of(context)`, Arabic rules built in; `app_theme.dart`).
- `data/`: `dto/` (`user_dto`, `school_dto` with the JSON helpers and Tunis day/instant mapping, `student_dto`), `remote/` (`auth_api`, `school_api`, `students_api`, `planning_api`), `repository/` (`api_guard.dart` turns Dio errors into `ApiFailure`; one `*_repository_impl.dart` per repository; `dashboard_repository_impl.dart` builds Ma journée from the planning API, 5 days).
- `domain/`: `model/` (`AppUser`, `ChildSummary`, `LocalizedText`, `TeacherDashboard`, `password_policy`, `clock_time`, `reference` (Subject, Level, SchoolYear), `session`, `student`, `group`), `repositories/` (auth, dashboard, reference, student, group, planning).

## 3. Run it

```bash
docker compose -f infra/docker-compose.dev.yml up -d          # PostgreSQL on localhost:5433
cd backend && cp .env.example .env                              # then set JWT_SECRET (openssl rand -base64 48)
mvn spring-boot:run                                             # API on :8080, dev accounts seeded
mvn test                                                        # needs Docker running (Testcontainers)
cd app && flutter run -d chrome                                 # talks to http://localhost:8080/api/v1
flutter analyze && flutter test
```

- Uploaded files in development: `backend/data/files/` (git-ignored); delete it with the database to start clean.
- Web preview without the debugger: `flutter build web --release --pwa-strategy=none --dart-define=API_BASE_URL=http://localhost:8080/api/v1` (`--pwa-strategy=none`: the default offline cache kept serving an old build in the user's Chrome, a pupil shell for the owner), then `python3 -m http.server 5050` in `app/build/web`, open http://localhost:5050.
- Android emulator: `adb reverse tcp:8080 tcp:8080` first (debug builds allow plain http).
- **Dev test accounts**: usernames in `backend/src/main/resources/application-dev.yaml` (owner under `admin:`, teacher username, student username, parent phone); their passwords in `backend/.env` (`TEACHER_PASSWORD`, `ADMIN_PASSWORD`, `DEV_STUDENT_PASSWORD`, `DEV_PARENT_PASSWORD`; git-ignored, the repository is public). Do not paste them in chat. `cdp-screens.mjs` reads them from there itself. To test a child or a parent without reading that file: sign in as the teacher, open a child's Fiche, then "Créer un accès" (child without login) or "Réinitialiser le mot de passe": the login details window shows a temporary password once, and the first login asks for a new one.
- Signed-in screenshots: `infra/dev-tools/cdp-screens.mjs` (headless Chrome through the DevTools protocol; steps in a JSON file; `$key` values are read from the dev YAML so passwords stay out of logs). Hash URLs: `http://localhost:5050/#/enseignante/...`.
- Screenshots of a mockup or a page: headless Chrome (`"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --window-size=W,H --screenshot=out.png URL`). It cannot go below about 500 px wide: render phones at 600 and crop (right-to-left pages stick to the right edge).

## 6. Things to know

- Times: Tunisia is UTC+1 all year; the app shows and enters Tunisian times whatever the device zone (`core/l10n/tunis_time.dart`), the server uses `Africa/Tunis`.
- French plurals: French puts 0 in the singular, so every plural needs an explicit `=0{...}`; `test/core/plurals_test.dart` checks both ARB files.
- State management: one Cubit per screen or panel (`view/stateManager/<feature>/`), `LoadStatus` loading/ready/failure, actions return their `ApiFailure` (or null) so the screen words the result. Panels and dialogs live above the shell: pass the Blocs they need with `BlocProvider.value` (see `StudentFormPanel.open`).
- Motion: `FadeRise` for cards, panels slide from the reading side, dialogs fade and grow, attendance tiles ease between colors, the week slides on navigation; all of it is off when the system asks for less motion.
- Dev database (Docker volume `ngclass-dev-db`): holds demo children, groups and sessions created through the API (invented names); only two children have their own login. `docker compose -f infra/docker-compose.dev.yml down -v` resets it (the seeders recreate the dev accounts, one subject and one group).
- The client's open questions (`docs/01-product/05-OPEN_QUESTIONS.md`): decide with the recommended default when blocked, tell the user.
- Launcher icons for Android/iOS are still Flutter defaults: wait for the vector logo, then use `flutter_launcher_icons`. Web icons and favicon already come from the NG symbol.
- Widget tests build plain `MaterialApp`s without `AppTheme` (google_fonts cannot download in tests). Without `AppTheme` there is no `AppFonts` extension, so `AppText` falls back to the default font; the test font is much wider than the real one, which is good at catching rows that cannot shrink.
- Fonts: google_fonts serves one family per weight. Never reuse a `fontFamily` name with another weight: build text styles with `AppText.of(context).style(...)` (or `inScript` for the wordmark and the language toggle), which asks google_fonts for the right weight.
- Screenshots of signed-in screens: the browser pane could not reach a local server in this setup; use `infra/dev-tools/cdp-screens.mjs` (see 3).
- Form errors: a `FormField` keeps the text its validator returned, so a message would stay in the old language after the switch. Forms whose validators return text (login, `PasswordForm`) set `autovalidateMode: always` on each field after the first refused submit (a Form-level setting would run the old validators). Forms driven by a Cubit keep error codes and word them in `build` (student form).
- Arabic text with numbers: a number written with spaces ("22 345 678") is reordered right to left inside Arabic text ("678 345 22"). Write numbers without spaces in Arabic strings, or show them in their own left-to-right widget. Do not use Unicode direction characters in ARB files: the analyzer flags them in the generated code.
- `DioClient.onSessionExpired` is a static callback wired in `injection.dart` (`startSession`).
- Changing the password does not sign out other devices (by design for now).
- The canvas board "Ma journée" had its content dragged into a separate piece (`Piece-de4z`); harmless, offer the user to merge it back if they want a clean canvas.
- Arabic month names: dates are written with intl's `ar_DZ` locale (`AppLanguage.dateLocale`), which has the Maghreb names used in Tunisia (جانفي، فيفري، جوان، أوت) and Latin digits. Load both date languages with `initializeAppDates()` (in `main.dart` and in every test that formats dates); never format a date with `language.code` (user decision 2026-10-06, `test/core/formatting_test.dart`).
- `fullDate` writes "1er" for the first day of a month in French ("du 1er septembre 2026").
- Mixed scripts on one line: a French group name or reason inside an Arabic line (or the reverse) gets reordered ("· · 10:00", a period jumping to the front). Wrap the inserted text with `isolated()` (Unicode isolate, from `core/l10n/formatting.dart`), or `keptTogether()` for a short name that must not split over two lines on a phone. Escapes in Dart code are fine; never put the characters themselves in ARB files.
- The web build needs the API address: `flutter build web --release --dart-define=API_BASE_URL=http://localhost:8080/api/v1`. Without it every sign-in fails with "Une erreur est survenue". `cdp-screens.mjs` now prints the page's console errors.
- Responsive guard: `test/view/responsive_test.dart` pumps screens inside their shell at 320x568 up to 1920x1080, FR and AR, and fails on any overflow. Add every new screen to it.
- Screenshots: `cdp-screens.mjs` has a `{"file":"/abs/path.pdf"}` step that answers the app's next file picker (real uploads through the web app), and a `{"signin":"student","lang":"ar"}` step (admin, teacher, student, parent; `$admin.username` reads a key inside a YAML block). It signs in at 1440 x 900, where its click points belong, so any viewport can follow. Never sign in with clicks measured at another size.
- Pupil wording: pupil-only strings use "tu" (`weekSummary`, `noNotificationsHintStudent`); `placeLabel(..., family: true)` writes "En classe" for pupils and parents and isolates the room name. Shared screens (login, choose password) stay in "vous".
- The student home reads the shell's `NotificationsCubit` ("Du nouveau"); once its list is loaded, a changed unread count reloads the list. Test helper `test/helpers/student_fixtures.dart` holds a pupil's two weeks and their changes.
- Flutter web and a new plugin (seen twice, with `file_picker` and with `image_picker`): after `flutter pub add` of a plugin with a web part, a release build may keep an old `web_plugin_registrant.dart` (cached under `app/.dart_tool/flutter_build/<hash>/`), and the plugin then fails at run time ("pickFile() has not been implemented"). Delete those `flutter_build/<hash>` folders and build again; check with `grep -c __file_picker_web build/web/main.dart.js`.
- `file_picker` 13: static `FilePicker.pickFile(...)` returns a `PlatformFile`, read it with `readAsBytes()` (the old `FilePicker.platform` and `withData` are gone).
- Page images come from `localhost:8080` while the app runs on `:5050`: they load because the API's CORS rules cover `/api/v1/files/*` too. Keep it that way if CORS changes.

- Numbers in a table column: a left-to-right number with `TextAlign.start` aligns to the left even in Arabic, away from its heading. Wrap it in `Align(alignment: AlignmentDirectional.centerStart)` (see `_Count` in `teachers_screen.dart`).
- Hints: examples use "Ex. : …" / "مثال: …"; a field typed left to right (username, email, link) gets a plain Latin example in Arabic, without an Arabic word around it.
- Copy style: short plain sentences, "vous", no long dashes.
- Free text someone wrote (instructions, later comments) can be in either language: give its `Text` `textDirection: writtenDirection(text)` (`core/l10n/formatting.dart`, intl's `Bidi`), or a French period jumps to the front in the Arabic app. `formatting.dart` imports intl with `hide TextDirection` (intl has its own).
